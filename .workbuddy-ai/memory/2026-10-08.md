## Key decisions / gotchas worth remembering

- **DB:** SQLAlchemy over `DATABASE_URL` — SQLite locally, Postgres on Render, same code.
  `alembic upgrade head; uvicorn ...` with `;` not `&&`, because the app's `create_all`
  is the safety net.
- **CREDIT/DEBIT vs inflow/outflow:** stored as CREDIT/DEBIT per PRD §8.2; mapped to
  inflow/outflow only at the ML boundary in `services/cashflow.py`.
- **Consent gate lives in exactly one place** — `cashflow._load_rows`. Everything
  downstream inherits it. Expired/revoked consents still *list* the account (so the UI
  can show status) but contribute zero transaction data.
- **CR-001 (open, ML lane):** `biznoria_ml.metrics.growth_trend` is broken — a series
  growing 10x or 50x over a year scores the same as flat (50.24). It normalises a
  per-day slope by *daily* volatility. 20% of the credit score is therefore pinned, so
  the score can never reach "strong" (≥75). I did **not** edit `ml/` (lane boundary);
  instead I made the backend's trend label independent of it. Fix proposed in
  `docs/DECISIONS.md`.
- **`.gitignore` trap:** an edit silently dropped the `data/` rules — a 6 MB DB and the
  CSV cache were about to be committed. Always `git status data/` after touching
  `.gitignore`.
- **pytest collision:** `backend/tests` and `ml/tests` are both packages named `tests`.
  Fixed with `backend/__init__.py` (→ `backend.tests.*`) + root `pytest.ini`.
- **Additive-only contract changes** (CR-002): the frozen schemas were too minimal to
  render PRD §5.1–§5.6 (consent status, trend, drivers, before/after). Added fields,
  renamed/removed nothing.

### Integration gaps found (frontend lane, NOT blocking)

1. `frontend/src/api/types.ts` mirrors **only the frozen contract fields**. The frontend
   therefore never reads the additive P0 fields the backend already returns, so these
   PRD-required surfaces are missing from the UI:
   - §5.2 health `trend` + `insights` + `top_expense_categories`
   - §5.3 `consent_status` / `consent_expires_at` / `institution_name` / `masked_account`
   - §5.4 forecast `status` + `drivers`
   - §5.5 credit `weights` (CreditReadiness.tsx hardcodes the "20%" labels)
   - §5.6 simulator `impact` / `impact_label` + before/after comparison
   Highest-value remaining work for the demo — all data is already on the wire.
2. The frontend never sends `X-Role` / `X-SME-Id`, so the API always treats the UI as
   officer and the "View as: SME customer" toggle is cosmetic. Worse: `App.tsx::SmeHome`
   calls `useSmes()` → the **officer-only** `GET /api/v1/smes` list, so wiring real SME
   headers would 403 it. A real SME surface needs either a hardcoded demo SME id or a new
   `/api/v1/me` endpoint (new endpoint ⇒ needs a CR in docs/DECISIONS.md).

### How to run (two terminals, from repo root)

```
# terminal 1
pip install -r backend/requirements.txt
uvicorn app.main:app --reload --app-dir backend      # http://localhost:8000

# terminal 2
cd frontend && npm install && npm run dev            # http://localhost:5173
```

No `.env` needed: the client defaults to `http://localhost:8000`, which matches.
