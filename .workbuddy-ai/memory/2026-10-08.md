## Key decisions / gotchas worth remembering

- **DB:** SQLAlchemy over `DATABASE_URL` — SQLite locally, Postgres on Render, same code.
  `alembic upgrade head; uvicorn ...` with `;` not `&&`, because the app's `create_all`
  is the safety net.
- **CREDIT/DEBIT vs inflow/outflow:** stored as CREDIT/DEBIT per PRD §8.2; mapped to
  inflow/outflow only at the ML boundary in `services/cashflow.py`.
- **Consent gate lives in exactly one place** — `cashflow._load_rows`. Everything
  downstream inherits it. Expired/revoked consents still *list* the account (so the UI
  can show status) but contribute zero transaction data.
- **CR-001 (open, ML lane):** `biznoria_ml.metrics.growth_trend` is broken — a series
  growing 10x or 50x over a year scores the same as flat (50.24). It normalises a
  per-day slope by *daily* volatility. 20% of the credit score is therefore pinned, so
  the score can never reach "strong" (≥75). I did **not** edit `ml/` (lane boundary);
  instead I made the backend's trend label independent of it. Fix proposed in
  `docs/DECISIONS.md`.
- **`.gitignore` trap:** an edit silently dropped the `data/` rules — a 6 MB DB and the
  CSV cache were about to be committed. Always `git status data/` after touching
  `.gitignore`.
- **pytest collision:** `backend/tests` and `ml/tests` are both packages named `tests`.
  Fixed with `backend/__init__.py` (→ `backend.tests.*`) + root `pytest.ini`.
- **Additive-only contract changes** (CR-002): the frozen schemas were too minimal to
  render PRD §5.1–§5.6 (consent status, trend, drivers, before/after). Added fields,
  renamed/removed nothing.

## BUG FIX — blank white page on every role switch / View click (19:05–19:25)

**Symptom:** clicking "View" on an SME row, or either "View as" role button, gave a
completely blank white page.

**Root cause (found, not guessed):** `TypeError: Cannot read properties of undefined
(reading 'stability')`. In `frontend/src/pages/SmeDetail.tsx`, `Health`, `Cashflow` and
`ForecastPanel` passed their JSX **as children** to `<QueryState>`:

```tsx
<QueryState isLoading={isLoading} isEmpty={!data} ...>
  <Card><Stat value={data!.stability.toFixed(1)} /></Card>   {/* evaluated EAGERLY */}
</QueryState>
```

JSX children are evaluated by the *caller*, before `QueryState` can branch on
`isLoading`. So on the first render `data` is `undefined`, `data!.stability` throws, and
the `!` is a TypeScript-only assertion that does nothing at runtime. With no error
boundary, the throw unmounted the entire tree → white page. Both entry points reach
`SmeDetail`, which is why *every* button appeared broken.

**Why it was hard to see:** `renderToString` with a pre-seeded query cache PASSED —
seeding made `data` defined on first render, hiding the bug. Only a client-side render
with a *cold* cache reproduces it. jsdom + RTL was needed (Chromium/agent-browser was a
500 MB detour — jsdom is ~2 MB and enough).

**Fixes applied:**
1. `components/ui.tsx` — `QueryState.children` is now a **render function**
   (`children: () => ReactNode`, called as `children()` only after the guards pass).
   This structurally prevents the whole bug class.
2. `pages/SmeDetail.tsx` — the 3 call sites updated to `{() => (...)}`.
3. `App.tsx` — added an **ErrorBoundary** so any future render error shows a visible
   message + "Try again" instead of a blank page (worst possible demo failure).
4. `App.tsx` — `openSme` / `backToPortfolio` / `switchRole` are now `useCallback` with
   functional-update bail-outs (`prev => prev` when unchanged), so identities are stable
   and state updates are idempotent — no render-loop class of bug.
5. `App.tsx` — `SmeHome` now handles `isError` (previously a failed SME-list fetch
   silently showed "No business linked to this login yet.").

**Verified:** reproduction went from `TypeError` → 0 errors; SME view renders with real
data (Stability 76.5, Growth 50.2, Liquidity 100.0, Revenue consistency 84.8, Repayment
50.0, Expense ratio 0.54); officer click returns to the 50-row portfolio. `tsc --noEmit`
clean, `npm run build` clean, existing 5 frontend tests pass.

**Files changed:** `frontend/src/components/ui.tsx`, `frontend/src/pages/SmeDetail.tsx`,
`frontend/src/App.tsx` (+ `frontend/package.json` / `package-lock.json` from the esbuild
fix). Frontend-lane files — flagged to Ifeanyi since backend is his lane.

**Lesson:** never pass `data!` inside JSX children of a conditional-rendering wrapper.
Pass a render function, or early-return like `Accounts.tsx`/`CreditReadiness.tsx` do.

### ⚠️ The trap that caused a white screen

Changing `tailwind.config.js` while the Vite dev server is running does **not** reliably
reload Tailwind's PostCSS config. `@apply bg-ink-950` then throws
`The bg-ink-950 class does not exist` → **the whole stylesheet fails to compile → white
page**. Fixes applied:
1. `index.css` base/components layers are now **plain CSS with hex values**, so a stale
   config can never take the stylesheet down.
2. **Always restart the dev server after editing `tailwind.config.js`.**

Also: `role="tab"` on the segmented toggle made `getByRole("button")` fail in tests —
switched to plain buttons + `aria-pressed`.

**Verified:** tsc clean · `npm run build` clean · 5 existing frontend tests pass ·
full jsdom render of portfolio → SME → simulator → role switch with **0 console errors**.

## Persona sign-in — role enforcement made real (22:30–22:45)

**Why:** the PRD §11 two-role story was *cosmetic*. The frontend never sent `X-Role` /
`X-SME-Id`, so the API always saw an officer — a judge watching the network tab would
catch it. Worse, `App.tsx::SmeHome` scraped the officer-only `GET /smes` list to find the
customer's own id, so sending real SME headers would have 403'd it.

**Design decision (with Ifeanyi):** no password login. PRD §5.7 puts real auth in P1, and
the backend already enforces `X-Role` + `X-SME-Id`. So: a **persona picker** that sets a
real session. Password auth = build risk + demo risk for zero judge value.

**Built**
- `components/SignIn.tsx` — full-screen persona picker. Officer → straight in. SME →
  searchable business directory, then Continue. Renders *before* any session exists, so the
  directory fetch carries no role headers and the backend answers as its default principal.
- `api/client.ts` — `Session { role, smeId }` + module-level `setSession()`; every request
  now carries `X-Role` / `X-SME-Id`. `getSession()` exposed for debugging.
- `App.tsx` — session gate; `SignIn` when null. **`SmeHome` deleted.** An SME session is
  always scoped to `session.smeId`, never a client-supplied id. `queryClient.clear()` on
  sign-in/out so one persona's cached data can never leak into another.
- `TopBar.tsx` / `Sidebar.tsx` — persona chip + sign-out. The capsule toggle is kept as a
  quick switch (defaults the SME to the first business) and the persona chip always shows
  which business is in view, so it is never a silent identity change.

**Verified**
- Frontend (jsdom): sign-in → officer → portfolio → sign out → SME → own business →
  **0 officer-only calls after SME sign-in**; 7 requests carried `X-Role: sme` + `X-SME-Id`;
  0 console errors.
